هر کسی که تلاش کرده باشد چند هزار واژه انگلیسی را با جعبه لایتنر سنتی حفظ کند، دیر یا زود با «بهمن مرورهای روزانه» روبه‌رو شده است. کافی است لغتی را که یک ماه بلد بودید یک‌بار اشتباه جواب بدهید تا سیستم سنتی آن را به خانه اول برگرداند؛ دقیقاً کنار لغاتی که پنج دقیقه پیش برای اولین بار دیده‌اید.

در طراحی **[Readner (لایتنر پرو مکس)](https://mohsen-niksirat.github.io/Leitner-Pro-Max/)** در قالب وب‌اپ آفلاین (PWA) و اپلیکیشن نیتیو اندروید با Kotlin، جعبه‌های ثابت را کنار گذاشتم و موتور علمی **FSRS (Free Spaced Repetition Scheduler)** را مستقیماً به خواننده داخلی کتاب‌های PDF و بانک ۴٬۵۰۰ واژه سطح‌بندی‌شده CEFR متصل کردم.

## چرا مدل‌سازی پایداری حافظه از شماره جعبه دقیق‌تر است؟

حافظه بلندمدت انسان با یک خطای تکی صفر نمی‌شود؛ واژه‌ای که سی روز در ذهن مانده خیلی سریع‌تر از یک واژه کاملاً جدید تثبیت مجدد پیدا می‌کند. الگوریتم FSRS این رفتار طبیعی مغز را با سه متغیر کلیدی مدل می‌کند:

* **پایداری ($S$):** تعداد روزهایی که طول می‌کشد احتمال یادآوری یک کارت از ۱۰۰٪ به ۹۰٪ برسد.
* **دشواری ($D \in [1, 10]$):** پیچیدگی ذاتی آن لغت برای کاربر مشخص که پس از هر پاسخ (`دوباره`، `سخت`، `خوب`، `آسان`) به‌روز می‌شود.
* **احتمال یادآوری ($R$):** احتمال به خاطر آوردن واژه پس از گذشت $t$ روز بر اساس منحنی فراموشی توانی:

```javascript
// FSRS v4.5 power-law forgetting curve and target interval solver
const DECAY = -0.5;
const FACTOR = 19 / 81; // Ensures R(S, S) === 0.90

export function retrievability(elapsedDays, stability) {
  if (stability <= 0) return 0;
  return Math.pow(1 + (FACTOR * elapsedDays) / stability, DECAY);
}

export function nextIntervalDays(stability, desiredRetention = 0.9) {
  const raw = (stability / FACTOR) * (Math.pow(desiredRetention, 1 / DECAY) - 1);
  return Math.max(1, Math.round(raw));
}
```

زیبایی ریاضی ثابت `FACTOR = 19 / 81` با توان `-0.5` در اینجاست که وقتی دقیقاً به اندازه پایداری کارت زمان گذشته باشد (`elapsedDays === stability`)، مقدار یادآوری دقیقاً برابر `0.90` خواهد بود. حتی اگر کاربر چند روز دیرتر به سراغ مرور بیاید و باز هم لغت را به یاد بیاورد، الگوریتم متوجه موفقیت در احتمال پایین‌تر شده و جهش پایداری بزرگ‌تری به کارت می‌دهد.

## حذف اصطکاک بین مطالعه کتاب PDF و ساخت فلش‌کارت

بزرگ‌ترین دلیل رها کردن اپ‌های فلش‌کارت، زحمت ساخت کارت جدید است: خروج از کتاب، کپی کردن جمله، جستجوی تلفظ و وارد کردن دستی معنی تمرکز مطالعه را از بین می‌برد.

در Readner، محیط مطالعه PDF و موتور مرور از یک پایگاه داده مشترک استفاده می‌کنند:

1. **استخراج در بافت واقعی جمله:** با انتخاب هر کلمه در متن PDF، هم خود واژه و هم جمله پیرامون آن به‌عنوان مثال واقعی ثبت می‌شود.
2. **غنی‌سازی فوری آفلاین:** اگر واژه در دیکشنری داخلی ۴٬۵۰۰ لغتی CEFR موجود باشد، سطح دشواری (`A1` تا `C2`)، تلفظ فونتیک و ترجمه در کمتر از ۴ میلی‌ثانیه بدون اینترنت تکمیل می‌گردد.
3. **شبکه معنایی WordWeb:** یادگیری لغات جزیره‌ای ماندگاری کمی دارد. گراف تعاملی WordWeb هم‌خانواده‌ها، مترادف‌ها و ریشه‌های مشترک را به شکل بصری نمایش می‌دهد تا شبکه تداعی در ذهن شکل بگیرد.

## تراکنش‌های اتمی در IndexedDB برای کارکرد مطمئن آفلاین

وقتی کاربر در مترو یا حالت پرواز کارت‌ها را مرور می‌کند، به‌روزرسانی وضعیت کارت و ثبت لاگ مرور باید کاملاً همگام ذخیره شوند. اگر تب مرورگر میانه دو عملیات جداگانه بسته شود، آمار یادگیری با زمان‌بندی کارت‌ها ناهماهنگ خواهد شد:

```javascript
export function commitReviewAtomic(db, updatedCard, reviewLogEntry) {
  return new Promise((resolve, reject) => {
    const tx = db.transaction(["cards", "review_logs"], "readwrite");
    tx.objectStore("cards").put(updatedCard);
    tx.objectStore("review_logs").add(reviewLogEntry);

    tx.oncomplete = () => resolve(updatedCard);
    tx.onerror = () => reject(tx.error);
    tx.onabort = () => reject(new Error("IndexedDB review transaction aborted"));
  });
}
```

قرار دادن هر دو جدول `cards` و `review_logs` درون یک تراکنش واحد `readwrite` تضمین می‌کند که یا هر دو تغییر با هم ثبت می‌شوند یا هیچ‌کدام اعمال نمی‌گردند؛ دقیقاً هم‌تراز با تراکنش‌های SQLite Room در نسخه اندروید.
